This URL is still publishing the checked-in /docs folder. That copy is not the hosted app, and it has no Supabase keys baked in.

You do not re-add secrets after every push. Repository Actions secrets stay set. The login error appears because GitHub Pages is serving this folder instead of the workflow artifact that was built with those secrets.

One-time fix

  1. Open Pages settings → Build and deployment → Source → GitHub Actions (not “Deploy from a branch” / /docs).
  2. Confirm Actions secrets already include VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY. Add them only if they are missing.
  3. Open Actions → GitHub Pages → Run workflow. Wait about a minute.

After that

You only wait when the GitHub Pages workflow actually ran. A push to main from a cloud agent often does not start it. If the live site looks old, click Run workflow once — do not touch secrets.
